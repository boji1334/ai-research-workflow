# 项目接手与访谈

## 顺序与记录

1. 阅读材料，记录每条关键事实的来源、日期与可信度。用户明确要求优先于历史快照；旧 GPU 分配、数据划分或期刊目标须核实是否仍适用。
2. 合并询问真正影响研究方向的事实缺口。每次问题量以用户易回答为准；不要一次甩出完整问卷。
3. 项目事实澄清后，进入论文目标与周期询问。用户已明确说过的内容直接继承。
4. 形成研究协议，记录未知项。仅当剩余未知项不会改变任务、科学解释、资源或评价公平性时，才可开始相关研发；否则先解决缺口。

区分四类记录：已有证据支持的事实、用户指定的约束、待验证假设、尚未知事项。不要将自己的猜测填成项目事实。

## 项目必问范围

按材料缺口选择提问，不逐字照念：

- **任务与瓶颈**：分类、目标检测、分割、异常检测/定位还是其他任务？已有失败实例与瓶颈证据是什么？重点类别或子集、错误代价和应用场景如何？
- **数据角色**：真实、合成、未标注、外部数据分别承担什么作用？是否存在同一工件、批次、连续帧或近重复样本跨集合？标注质量和类别长尾如何？
- **学习设置**：少样本按样本、工件、类别还是支持集计算？自监督预训练看过什么数据？异常检测是否训练时只使用正常样本？
- **基线与历史**：当前代码、版本、配置、权重、划分、指标脚本和实际结果在哪里？尝试过什么？哪些结果可复现，哪些只剩摘要？
- **研究边界**：用户固定的主线、已发表或已作为其他论文贡献的内容是什么？哪些模块可改？是否允许外部预训练、额外数据或改变推理代价？
- **定位空间**：哪些任务/技术是硬约束，哪些是偏好？用户是否允许调整具体研究问题？先读已有约定，只有真实歧义才补问；研究定位按 [机会选择](positioning.md) 进行，不自行把普通检测切换成未知类别等新任务。
- **资源与执行责任**：本地/远程运行位置、可用设备、训练与存储预算、已有环境、当前活动任务及执行者。先检查已有条件，不默认安装 Docker 或完整框架。

同一视觉任务仍可能包含不同协议；定位到具体任务后再选择文献和指标。

## 论文目标与周期

- 有目标期刊：记录期刊与用户关注的栏目/要求。以期刊官方范围和近期相关论文核对适配。
- 暂无期刊：询问目标级别、分区体系及年份、OA 偏好和其他硬约束。不要把不同分区体系混为一谈；无法核实的当前分区保留待查。
- 周期：记录用户可接受的天数或截止日期、时区，安排小试、完整实验、审查和必要的补实验时间。算力预算与墙钟周期分别记录。
- 成功标准：与任务的强基线、波动、重点类别、泛化和成本对应。不向用户兜售“保证首创”或“保证顶刊”。

## 已有项目的接续

先恢复项目已有协议、候选、运行和待核项。只询问新出现的关键缺口，不重复整套访谈。先前未完成访谈时，继续完成它；早期宽泛的“继续”不等于补齐缺失事实。

新项目可复制 [协议模板](../assets/research-contract.json)。该模板服务于辅助工具；已有格式可按等价内容记录，不强制迁移或另建平行账本。
