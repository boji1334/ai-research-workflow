# 面向用户目标的设计立项准入

在候选训练前使用，属于现有模块审查的必答内容。它判断“是否有充分依据值得围绕约定论文目标投入”，不提前宣告效果成立、期刊录用或方案零缺陷。仅有新意或可运行性不满足准入。

## 四项必须回答的问题

| 维度 | 立项需要的依据 | 不足以放行的情况 |
|---|---|---|
| 目标适配 | 记录用户目标、分区口径/年份和发表路线；核对目标期刊范围或同领域同目标层次的代表性论文，从问题价值、贡献分量、论证和可行实验范围说明匹配理由与差距 | 只有“预计二区/顶刊”、论文列表、公式差异或新命名，没有对具体贡献的比较 |
| 数据针对性 | 数据角色、样本/工件/类别特征、标注与分布约束，以及训练/开发中可定位的失败或限制；解释为何这些事实支持拟解决的问题 | 仅沿用当前数据和模型；辅助任务有现象，却没有说明它与项目下游问题的关系 |
| 机制必要性 | 最近邻已解决的范围、新机制改变的信息/监督/更新、相对成熟方法和更简单方案的价值，以及可证伪预测 | 常规组合或参数变化只有“没见过同式”；复杂结构不比简单方法多提供相关能力；用未来涨分代替立项理由 |
| 设计可靠性 | 关键假设、信息流、公式、边界情形和实现路径闭合；主动反例/退化检查，已知关键缺陷的修复与复核证据；剩余假设及对应实验 | 要学的信息在运算中被消掉、目标与任务不匹配、监督泄漏、关键路径不成立，或仅有修复计划 |

没有特定期刊时可按已约定级别寻找合适参照，但原文、范围和所声称的分区身份须核实；来源不可得或口径未定要写明，不捏造对标材料。发表路线单独记录，不当作创新分数。代表论文不是统一录用规则，也不需要机械凑固定篇数。

数据依据可来自已有错误、训练样本分析、标注/分布事实或与数据条件相符的明确结构限制；不要求先用训练证明新机制必然提高指标。病因尚未确立时标为假设，并说明现有证据怎样支持这一假设、什么观察会否定它。若最关键的数据—机制联系仍只是猜测，先补必要性依据，不以“大方向相关”放行。

成熟组件可以构成实质机制增量，按整体信息流和行为审查。最近邻已有同一方向不否定全部研究；仅换任务名称、换场景标签或修改评价也不增加贡献。

## 设计反例与必要性检查

按主张选择真正能影响决策的检查，不强制每个项目运行相同清单：

- 目标能否区分它声称区分的两种错误？差分、归一化、投影或池化是否消除了关键方向/幅值？
- 固定输入、常数目标、单候选、对称/平移或退化情形下，是否退回已知方法、出现捷径或丢失有效信号？
- 最接近的方法或直接回归/普通正则化能否表达同样作用？若能，新设计是否还有具体且有必要的增量？
- 目标来源、detach、梯度、训练/部署和数据权限是否与论证一致？额外容量/代价是否值得？

理论或合成检查只支持其适用范围，不冒充真实数据收益。尚未测得收益、完整消融和泛化属于后续实验事项；它们不替代也不自动否定方案层面的立项依据。

## 明确结论及训练边界

使用 [立项记录](../assets/admission.md) 或项目等价记录，绑定目标/协议、候选族、方法或代码版本、数据证据与来源版本。已有研究记录可复用，不另建竞争账本。

| 设计结论 | 行为 |
|---|---|
| `design_supported` | 四项核心依据充分，已知关键设计阻断项处理并有复核证据；可以评估限定小试的工程、预算及执行准入。仍无已测效果或录用承诺 |
| `needs_design_revision` | 目标适配、数据联系、机制必要性或可靠性存在影响核心立项的不足/未知；返回具体设计/事实核验，不启动候选训练 |
| `known_enhancement` | 等价证据支持归为已知方法；保留署名归属及结果，可作有必要、已纳入协议的基线或对照，不作为新主创新放行 |
| `close_candidate` | 关键依据被否定、没有适用价值或累计修复/资源到限；保留负结果与原因，不更名复活 |

`proceed_to_pilot` 必须同时有当前版本的 `design_supported`、可区分解释的实验及可用预算/执行前提。任何核心项不足不以其他维度“总分较高”抵消；不捏造创新评分、成功概率或“已达到某分区”的认证。审查者给出依据与限度，主执行者对实际放行负责。

没有已测结果不等于设计不合格；设计合格也不等于效果未知可以无限训练。受限小试仍遵守原指标、数据角色、候选历史、两轮修复上限和截止。修复或新版本复核受到变化影响的项目，未改变且仍有效的依据直接继承；新机制不沿用旧批准。

立项待完善时可在既有授权/预算内做来源阅读、代数反例、训练数据事实检查，以及用既有权重的只读前向/梯度诊断，明确它们要补哪项依据与退出条件。合成单步数学检查不提供检测效果证据。带候选参数更新的 smoke、小训练、超参/种子效果比较均属于候选实验；改成 `diagnostic`、`probe`、`control` 或工程名称不改变准入与记账责任。已知方法的必要基线复现按原项目协议记录，不能用对照身份偷渡未获准的新方法。

现有 `research_guard.py` 不解析本记录、不判断论文质量。它的结构登记通过不替代本项科学与执行判断；旧项目/登记兼容，恢复时补齐相关记录而不重新初始化历史。
