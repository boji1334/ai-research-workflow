# 多源查新与文献证据

本流程用于机制查新和实验依据；不要求安装上游套件、MCP 服务或付费 API。使用当前已有的搜索、浏览、论文和代码访问工具。离线材料可以先做范围受限的核验，明确尚未覆盖近期工作。

## 检索与失败处理

1. 从瓶颈、机制/公式、监督信号和评价设置构造查询。先查核心机制及同义表达，再加任务名称；补近期工作、前向/后向引用和必要代码核对。
2. 视觉研究优先查会议/期刊官方论文库、出版社原文、OpenReview、arXiv，以及作者关联的公开实现；Crossref 用于 DOI/出版元数据交叉核验。通用搜索与学术索引用于发现线索，再回到原始来源。按任务选取互补来源，不机械套用医学检索渠道。
3. 记录实际访问的来源、查询、日期、筛选范围及版本。关键查新尽可能覆盖互补来源；做不到时记录缺口，不虚构覆盖率或全球首创结论。
4. 区分正常返回零条结果与超时、限流、凭据缺失、工具缺失、解析失败。单源故障时记录原因，用剩余来源、已有原文或另一个检索入口继续；不无限重试，也不自动安装服务或购买权限。
5. 记录停止原因：已完成约定检索范围、近期查询不再产生相关机制，或时间/访问预算到限。后者保留未覆盖项，不能作为排除已有工作的证据。

## 身份、版本与命题支持分别核对

- DOI、arXiv ID 或 OpenReview ID 先定位记录，核对标题、作者、年份、出版场所和版本。没有标识符时用标题与作者检索，并标明匹配依据。
- 预印本、会议版、期刊扩展版建立版本关联，保留各自的日期和差异；同一贡献不重复计数。仅标题近似不足以合并；扩展版新增机制也不能被去重隐藏。
- 身份状态使用 `verified`、`mismatch`、`unresolved`，并给原因。来源故障、全文缺失和一次搜索零结果都不等于文献不存在。
- 原文支持状态另列 `supports`、`contradicts`、`partial`、`not_assessed`。论文存在并不表示它支持某个命题，更不表示已读过其全文。
- 具体定位到页、节、公式、表或已核实代码位置。只能读摘要时标明证据层级，保持机制差异待核；不编造 DOI、引文、页码或代码行为。
- 记录更正、撤稿和版本变化，以实际查到的状态为准；不把引用量或作者声望当成机制正确性的证据。

## 查新交付

沿用项目记录或 [文献模板](../assets/literature.md)。交付查询与访问失败记录、版本关联、最近邻对照和未覆盖范围；最近邻要比较公式、数据接触、训练/推理路径及可区分实验。

找到足以否定新颖性的原文时更新模块审查；有性能收益的候选可保留为已知增强。证据冲突先保留两方定位与分歧，不靠多数来源投票。新材料进入下一版证据包，不追溯改写已经定稿的审查报告。
