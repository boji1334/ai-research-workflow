## Isolated procedure checks / 隔离行为检查

Three Codex subagents with fresh contexts receive only the assigned skill and one synthetic packet each, without expected verdicts, parent findings, other reports or shared issue ledgers. Reports are written to separate evaluation directories outside the repository. Scope excludes network, training, installations, live projects, repository changes and external messages; the first packet permits tiny synthetic algebra only. Each report is finalized before the parent reads and summarizes it.

- [Proposal readout](../tests/fixtures/proposal-readout/project.md): target comparison excerpts, two candidate mechanisms, project observations, existing review memos and proposed execution options.
- [Proposal continuation](../tests/fixtures/proposal-continuation/project.md): a version-bound design record, supplied dataset/method/source evidence, unmeasured effectiveness and a bounded remaining budget.
- [Target-fit check](../tests/fixtures/target-fit/project.md): a candidate with supplied data/technical rationale but an unsupported target-level claim and a proposed short training run before target comparison.

The source names, journal descriptions, figures and numbers are all synthetic and do not validate real paper identity, rankings, novelty or measured performance. Context isolation is conversational and task-scoped, not a filesystem access control.

## Limits / 验证边界

These tests check specific decisions from supplied inputs. They do not prove flawless reviews, improved research speed, real model gains, final acceptance, or a guaranteed journal level. Design admission is a mandatory procedural precondition, not a new machine-enforced scientific classifier. The unchanged registry does not read admission reports. Real projects still require actual source checks, dataset evidence, execution discipline and fair experiments.
