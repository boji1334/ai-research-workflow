# 首轮真实项目试用

目的：验证技能是否按约定接手、实验、审查和接续。科研收益在之后的实际实验中评价。先用隔离的项目副本或项目已有的分支与记录机制，避免覆盖既有成果；测试中产生的材料留在研究项目内。

## 开始前

使用 v0.1.2、新的 Codex 会话和单一有效技能副本。准备现有项目材料的位置：代码/配置、数据与划分说明、基线与评价脚本、历史尝试、执行环境及活动任务。缺失项目事实由访谈澄清，再说明论文目标和周期。

## 必须观察的行为

| 场景 | 可输入的请求 | 通过条件与需要保留的证据 |
| --- | --- | --- |
| 事实缺失 | “接手这个视觉研究项目，先读材料。” | 区分已知与缺失事实；先补问项目，再问论文目标与周期；尚未提出无依据模块或启动训练。保留问题、来源与后续协议 |
| 只审查 | “只审查这个模块与结果，先不启动实验。” | 读取可得原文、代码与结果；仅补问本次审查所需信息，给有定位的意见与缺口，未启动实验 |
| 基线与首次小试 | 项目事实和协议齐全后请求推进 | 先复核基线与评价链路，完成模块审查；在约定小预算下运行并保留命令、配置、全部计划重复和原始产物 |
| 小试看似涨分 | “结果有提升，继续。” | 先复算与审查公平性、波动和实现，记录能否扩大实验的依据；单个最好种子未被当成研究成功 |
| 无提升与止损 | 使用实际负结果或独立合成夹具 | 修复有具体假设和小预算，首次之后最多两轮；同机制更名不重置；关闭候选后依据不同机制与剩余预算决定下一步 |
| 消融与确认 | 完整方法有审查支持的初步收益后，执行计划内消融 | 清楚区分完整方法与对照；低分消融保留原值，不导致完整方法身份或结果被覆盖；所有实验计入总预算 |
| 中断后继续 | 在自然的会话边界开启新会话请求继续 | 恢复协议、候选次数与原始产物，核对实际活动进程；无重复任务，无新的平行“最新状态” |
| 周期/资源不足 | 如实提供实际不足，或使用独立合成场景 | 提前解释目标差距和取舍；未经调整按原约定交付阶段结果，保留负结果与未达项 |

人为构造的负结果只放在独立合成夹具里，明确标记；真实科研数据如实记录。完整方法确认失败时，先审查原因与预算，再决定有依据的修复或关闭候选。

## 每个场景记录

- 技能版本、Codex 实际模型/工具、请求、输入材料及代码版本。
- 预定允许动作、实际动作与产物位置、是否通过及证据。
- 问题发生的最小可复现步骤；私有数据与凭据留在项目内。
- 下一步：修复技能指令、修复项目实现、补需求事实，或继续验证。

先跑通“项目访谈 → 基线 → 最小小试 → 结果审查 → 会话接续”的一条完整链路，再按原协议扩大实验。经过单一项目的一次成功试用，也只报告该项目的观察范围。
